# DECISIONS.md

1. **Indexes.** I created a unique index on `attendance_logs(emp_code, date)` because it acts as our natural key, prevents duplicate punches on the same day, and speeds up lookups for punch-out, PATCH, and monthly aggregates. For sorting and range scans, I added `(date desc, emp_code)`, and `(status, date desc, emp_code)` for status filtering. On `employees`, `emp_code` is unique, with helper indexes on `(department, emp_code)`, `(department, joined_on)`, and `(joined_on)` for department listings and headcount calculations. I avoided copying `department` directly into attendance logs so data never becomes outdated if an employee changes departments.
2. **Punch-in race.** Instead of doing a check-then-insert which causes race conditions under load, both concurrent requests attempt to insert their document directly. The database unique index guarantees that only the first request succeeds; the second request raises a `DuplicateKeyError`, which the endpoint catches and returns as a 409 Conflict.
3. **Ranking ties.** I calculate ranks using MongoDB's `$rank` window function first, and only then apply the `rank <= limit` filter. Because `$rank` gives tied employees the exact same rank (e.g. 1, 2, 2, 4), everyone who shares the cutoff rank remains in the result, even if the total returned rows exceed the limit.
4. **Headcount calculation.** The department summary starts from attendance records, but uses `$unionWith` to pull in employees from the `employees` collection whose `joined_on` date is on or before month end. A final `$group` stage combines both sets, ensuring employees who had zero attendance logs in that month are still counted toward the department headcount.
5. **Scaling to 100x data.** At 100x scale, running heavy multi-collection pipelines over raw logs on demand would become too slow. I would maintain a daily summary collection rolled up per employee and updated at write time when punches occur. This keeps analytics reading only a few thousand aggregated records instead of scanning millions of raw logs.
